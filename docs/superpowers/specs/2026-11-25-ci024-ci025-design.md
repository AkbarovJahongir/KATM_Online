## Зачем

ТЗ 10.0 добавило два метода, которых не было в 9.16:

- **CI-024** — отчёт по остаткам/оборотам счетов (по филиалам) за дату.
- **CI-025** — сведения о гарантии.

В ТЗ у обоих URL указан как `{base url}/` без пути, поэтому путь — настройка.

## Настройки (`CreditBureauApiOptions`)

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `BalanceReportUrl` | `""` | путь CI-024, например `/katm-api/v1/...` |
| `GuaranteeUrl` | `""` | путь CI-025 |

Пустой URL — обработчик пишет в лог «URL не задан» и ничего не делает (очередь не читает, статусы не меняет, Telegram не шлёт).

## Контракт SQL-функций (делает команда БД, база `DBConnection`)

Обе функции — табличные, без параметров, возвращают только то, что нужно отправить сейчас (как `KATM_Report_001…023`). После отправки статус пишется в `Katm_Methods_Request_UpsertCiStatus` с `CiCode = 24 / 25` — функции должны по нему отфильтровывать уже отправленное.

### `dbo.KATM_Report_024()` — одна строка на пару «филиал + счёт»

| Колонка | Тип | В JSON |
|---|---|---|
| `loanKey` | int | ключ отчёта (не кредита); статус ведётся по `(loanKey, 24)` |
| `pHead` | varchar(3) | `pHead` (перезаписывается из настроек) |
| `pDate` | varchar | `pDate` — дата баланса, `yyyy-MM-ddTHH:mm:ssZ`, **не** перезаписывается |
| `departmentCode` | varchar(5) | `pDepartmentArray[].code` |
| `coa` | varchar(5) | `coaBalanceArray[].coa` (балансовый счёт, справочник 019) |
| `currency` | varchar(3) | `coaBalanceArray[].currency` (справочник 017) |
| `date` | varchar | `coaBalanceArray[].date` |
| `startBalance`, `debit`, `credit`, `endBalance` | decimal | одноимённые числа |

C# группирует строки: `loanKey` → один запрос, `departmentCode` → элемент `pDepartmentArray`, строка → элемент `coaBalanceArray`.

### `dbo.KATM_Report_025()` — одна строка на гарантию

`loanKey`, `pClaimId`, `pContractId`, `pTin`, `pNibbd`, `pGuaranteeType` (справочник A20), `pStartDate`, `pEndDate`, `pCurrency` (017), `pCreditAmount` (decimal), `pQuality` (036), `pSourceType` (113), `pForeignOrg` (041), `pGuaranteeInfo`, `pActivity` (A16), `pReason` (A17).
`pHead`, `pCode`, `pDate` (дата отправки) проставляет сервис.

## Поведение

- Обработчики `Ci024BalanceReportHandler`, `Ci025GuaranteeHandler` на `CiHandlerBase.ProcessCiRequestsAsync` — JWT, логи, статусы, Telegram как у остальных CI.
- Пока функции нет в БД (SQL 208 «Invalid object name»), репозиторий пишет предупреждение и возвращает пустую очередь — без падения и алертов.

## Допущения (сверить по PDF ТЗ 10.0 — текст извлёкся с искажениями)

- Поле валюты в CI-024 — `currency` (по JSON-примеру).
- ИНН в CI-025 — `pTin` (в таблице читается как `plnn`, в примере `pTiin`).

## Не входит

Отправка за период (`ICiPeriodHandler`), сами SQL-функции, валидация кодов справочников.
